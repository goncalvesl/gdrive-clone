# Cursor do inventário remoto

Implementado em 2026-10-26 com a [API pública Changes](https://developers.google.com/workspace/drive/api/guides/manage-changes). Quando o cache está vazio, obter `getStartPageToken` antes do inventário completo; salvar a árvore e esse cursor juntos depois de uma listagem completa. Assim, alterações ocorridas durante o inventário serão lidas no ciclo seguinte.

Nos ciclos seguintes, ler todas as páginas de `changes.list`, com `includeRemoved=true`. Sem mudanças, reutilizar a árvore persistida e avançar apenas o cursor. Mudanças de arquivos comuns são aplicadas por ID: atualizar o Entry, renomear/mover seu caminho dentro dos diretórios já conhecidos ou removê-lo do cache. Renomeações e movimentos de pastas já conhecidas dentro de pais conhecidos reescrevem, por ID, os caminhos da pasta e de toda a subárvore cacheada. A alteração dos Entries afetados e o cursor são gravados na mesma transação SQLite v5. Eventos de IDs desconhecidos/fora da raiz não alteram o cache local. Se um ID conhecido passar a apontar para um parent desconhecido, fazer inventário completo para distinguir movimento para fora de entrada numa pasta nova.

Criação, remoção/lixeira ou movimento para fora/parent desconhecido de pasta exige inventário completo, pois pode incluir ou esconder uma subárvore. Também fazem inventário completo eventos sem metadados suficientes e colisões de caminho. Nunca avançar cursor diante de falha HTTP, paginação incompleta/repetida, JSON inválido ou falha do inventário. Se a API rejeitar o cursor (HTTP 400/410), obter um cursor novo e fazer inventário completo; só então substituir cache/cursor. Ausência em um inventário completo continua sujeita às regras existentes: status/lixeira explícitos antes de inferir exclusão. O cursor e o cache são privados por perfil; tokens OAuth e conteúdo não entram nessa tabela além dos metadados já presentes nos Entries.

Mudanças em arquivos e movimentos/renomes de pastas conhecidas evitam a varredura recursiva. Criação/remoção de pastas e ambiguidades ainda usam inventário completo. Polling da Changes API continua periódico; notificações push permanecem futuras. Homologação real e medição de quota/desempenho ainda pendentes.
